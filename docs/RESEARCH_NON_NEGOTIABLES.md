# Research Non-Negotiables: Defender-Oriented CybORG JEPA

This document defines the strict, non-negotiable architectural and methodological constraints for researching **Joint-Embedding Predictive Architectures (JEPA)** for autonomous cyber defense in **CybORG**.

---

## 1. Information Boundary & Zero Simulator-Leakage
* **Strict Blue Observation Constraint**: The JEPA model input MUST ONLY consume data accessible within Blue's legitimate observation boundary $O_{t-h:t}^{Blue}$.
* **Simulator Ground-Truth Isolation**: True network state (full compromised status, process tables, internal Red actions, unobserved subnets) available in the CybORG simulator MUST NOT be fed into the Blue JEPA input encoder.
* **Separation of Probing vs. Input**: Ground-truth state is reserved strictly for off-line evaluation, diagnostic logging, representation probing (linear probing $z_t \to \text{true\_state}$), and oracle baseline comparisons.

---

## 2. Action-Conditioned World Modeling
* **Predictive Formulation**: The model MUST predict action-conditioned future representations:
  $$P(z_{t+k} \mid O_{t-h:t}^{Blue}, a_t^{Blue})$$
  rather than unconditioned passive state transitions.
* **First-Class Action Tokens**: Defensive actions $a_t^{Blue}$ MUST be explicitly embedded as structured input tokens (combining action type, target host/subnet, and parameters) rather than treated as implicit environment noise.

---

## 3. Anti-Collapse & State-Sparsity Guardrails
* **Trivial Identity Prediction Prevention**: Cyber-defense trajectories exhibit high spatial and temporal state sparsity ($>90\%$ of features remain static step-to-step). The model MUST NOT rely on unmasked full-state future target MSE without change-weighting or targeted spatial/host masking, which causes representation collapse toward identity prediction ($z_{t+k} \approx z_t$).
* **Latent Space Prediction**: The architecture MUST predict representations in latent space ($z_{t+k}$) generated by an EMA-updated target encoder $f_{\bar{\theta}}$, NOT reconstruct raw high-dimensional observation strings or log lines ($\hat{x}_{t+k}$).

---

## 4. Preservation of Reference Implementation
* **Zero Destruction of Working Baselines**: Existing Adult Income T-JEPA pipeline (`data.py`, `model.py`, `trainer.py`, `downstream.py`, `run.py`) MUST remain intact and functional as a known-working reference implementation.
* **Modular CybORG Architecture**: CybORG-specific code MUST live in dedicated directories (`cyborg/`, `docs/`, `experiments/`), ensuring baseline tabular T-JEPA and CybORG Cyber-JEPA can be compared cleanly.

---

## 5. Reproducibility & Research Rigor
* **Explicit Experiment Tracking**: Every trajectory dataset collection and training run MUST log random seeds, CybORG version (3.1), scenario config (`Scenario1b`), Red/Blue policy configurations, prediction horizon $k$, and evaluation metrics.
* **Offline Trajectory Dataset Strategy**: JEPA representation learning MUST operate on offline trajectory datasets collected across diverse policy combinations (`Random`, `Sleep`, `B_lineAgent`, `RedMeanderAgent`) to ensure reproducible GPU training decoupled from simulator CPU speed.
